## 3. 건축 공통 데이터 모델 초안

세 방식(블록·모듈·프리셋)을 하나의 **배치물(Placement)** 목록으로 표현해요. 기존 셀 조각은 그대로 두고(블록 레이어), 새 배치물은 별도 목록에 저장해요.

```js
// 정의 (코드 상수, 저장하지 않음)
BUILD_DEFS = {
  workbench: { kind: "station", n: "작업대", size: [1, 1], cost: { wood: 6, stone: 2 }, solid: true },
  hut_small: { kind: "preset",  n: "작은 오두막", size: [4, 3], cost: { plank: 20, stone: 6 },
               parts: [ /* 모듈 조각 목록: {def:"wall_wood", dx, dy, rot}, {def:"door_wood", ...} */ ],
               interior: { x: 1, y: 1, w: 2, h: 1 } },        // 가구 놓을 수 있는 칸
  wall_wood: { kind: "module", n: "나무 벽", size: [1, 1], cost: { plank: 2 }, edge: true },
  // kind: block(기존 셀 조각) | module(벽·문·창·지붕) | preset(완성형) | station(작업대·화로) | furniture
};

// 배치물 (저장 대상) — S.builds[id]
{ id: "b_1732790000_1",   // 고유 ID (생성 시각+순번)
  def: "hut_small",       // BUILD_DEFS 키
  x: 524301, y: 524288,   // 월드 셀 좌표(왼쪽 위)
  rot: 0,                 // 0~3 (90° 단위)
  lv: 0,                  // 층(추후)
  owner: "local",         // 멀티 대비 소유자
  t: 1732790000000,       // 생성 시각
  inner: [ { def: "bed", x: 1, y: 1, rot: 0 } ] }   // 건물 안 가구(로컬 좌표)
```

규칙
- **충돌 판정**: `wsolid()`에 "배치물 점유 칸 인덱스"(로드 시 `S.builds`로 재계산, 저장 안 함)를 더해요. 셀 레이어와 겹치면 설치 불가.
- **공통 기능**(미리보기·회전·검증·재료 표시·설치·취소·철거·이동·복사)은 `def.size`+`rot`만 보면 되도록 한 곳에 구현.
- **블록 레이어**(기존 `S.wedits`)는 그대로. 나중에 높이(블록 쌓기)가 필요해지면 `S.blocks["x,y,z"]`를 별도 추가해요.
- **렌더링**: 프리셋은 모듈 조각의 합으로 그려서 모듈형과 코드 공유. 처음엔 기존 벽·바닥 모델(셀 조각 그리기 코드)을 재사용해요.
- **집 안 가구**: 건물의 `inner` 칸에 기존 `FURN` 가구를 배치. 기존 '내 집' 방(`S.room`)은 유지해요(제거하지 않음).

## 4. 저장 데이터 변경 위험

| 위험 | 내용 | 대응 |
|---|---|---|
| 버전 | 새 필드(`S.builds`, 생존 상태, 통합 인벤토리)는 v3 구조에 없음 | `SAVE_VER=4`, `migrateSave`에 v3→v4 기본값 추가. 기존 필드는 지우지 않음 |

| 용량 | `localStorage` 약 5MB. `S.wedits`·발견 지도(`disc2`, 최대 3만 칸)가 이미 큼 | 배치물은 셀 단위가 아니라 건물 단위라 작음. 저장 크기를 테스트에서 측정 |

## 5. 기술 부채 · 위험 요소

- `index.html` 한 파일 4,091줄(약 438KB), 한 줄에 여러 문장이 있어 변경 단위 검토가 어려움. GDD 17.3 모듈 경계는 **새 시스템부터** 별도 구역(주석 블록)으로 모아 쓰고, 파일 분리는 아티팩트 게시 방식(한 파일)과 맞춰 나중에 결정.
- 테스트 전체 실행 약 35~40분(소프트웨어 WebGL). 새 시스템 테스트는 렌더링 없이 `window.__game` 상태로 판정하도록 작성.
- 2D·3D 두 화면 모두 그려야 함: 새 배치물은 3D와 2D(`draw2D`) 둘 다 표시 필요.
- 원격 플레이어·다른 마을 주민·VRM 용량 등 HANDOFF 8장의 알려진 문제는 이번 분석에서 코드상 그대로 남아 있음을 확인(변경 없음).
- 예전 작업 대기열의 남은 항목(보스 2종·도깨비 정예·26종 캐릭터)은 새 우선순위에서 전투(45)라 **보류**로 옮겼음 → `WORK_QUEUE.md`.

## 6. 권장 작업 순서와 첫 구현 단위

GDD 20장 순서(P1 → P2 → P3)를 따르되, MVP 수용 테스트의 빈칸(2·3·4·5·6·7)을 가장 빨리 메우는 순서로 쪼갰어요.

1. **P1-1 아이템 정의 통합(저장 변경 없음)** — `ITEM_DEFS` 하나에 재료·마을 아이템·가구·도구를 같은 ID 규칙으로 등록하고, 기존 `S.mat`/`S.inv`/`S.fin`은 어댑터(`itemCount`, `itemAdd`, `itemTake`)로 접근. 화면·저장은 그대로.
2. **P1-2 도구 아이템과 도구별 채집** — 돌도끼·돌곡괭이 제작, 나무는 도끼·바위는 곡괭이가 있으면 빠르고 많이(맨손도 가능하되 느리게). 내구도는 가볍게(수리 간단).
3. **P1-3 작업대** — `BUILD`에 작업대 추가, 작업대 근처에서만 열리는 제작 탭(판자·도구·기본 가구). 가구를 제작으로 얻을 수 있게.
4. **P2-1 공통 건축 모델 + 프리셋 배치** — `S.builds`(v4), 작은 오두막·작업장 프리셋, 미리보기·회전·검증·철거.
5. **P2-2 지은 건물 안 가구 배치**
6. **P3-1 허기·스태미나** → **P3-2 체온·기온** → **P3-3 수면=게임 시간**
7. **P3-4 작물 2~3종·물 주기·요리**

**첫 번째 구현 단위 = P1-1 + P1-2** (아이템 정의 통합과 도구별 채집)
- 완료 조건
  - 돌도끼·돌곡괭이를 제작 창에서 만들 수 있고, 퀵슬롯(기존 도구 줄)에서 선택할 수 있다
  - 도끼로 나무, 곡괭이로 바위·철광석을 캘 때 타격 수가 줄고 획득량이 늘며, 맨손으로도 느리게 캘 수 있다
  - 기존 저장(v3)을 그대로 불러와도 재료·아이템·가구 수가 변하지 않는다
  - 새 시나리오 테스트(`gathering_tools`)와 전체 회귀 통과, 아티팩트 사본에서 동작 확인
