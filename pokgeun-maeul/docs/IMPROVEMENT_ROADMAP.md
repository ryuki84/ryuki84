## 2. 우선 작업 3개 (승인 후 착수 제안)

### 작업 A — 회귀 테스트를 저장소로 (P0)
- **문제와 근거**: TOP 10의 1번.
- **목표**: 누구나 명령 한 줄로 기존 시나리오 테스트를 돌릴 수 있게 해요.
- **범위**
  - `tests/` 폴더와 루트 `package.json`(개발용 Playwright 의존성) 추가
  - 임시 폴더의 핵심 시나리오를 정리해서 옮기기: a1, k3, w7, g12, k4, tp, seam, ux, dd, mz, dn, mp, m4
  - 공통 실행기(정적 서버 + three.js 로컬 경로)와 `npm test` 추가
- **변경 파일**: 새 파일만 추가해요(`tests/*.js`, `package.json`, `tests/README.md`). 게임 코드는 바꾸지 않아요.
- **작업량 / 위험**: 중 / 낮음. three.js를 CDN 대신 로컬 `node_modules`에서 제공하도록 실행기만 손보면 돼요.
- **완료 기준**: 새로 받은 저장소에서 `npm i && npm test`로 전체 시나리오가 실행되고, 통과·실패가 표로 출력돼요.
- **롤백**: 추가한 파일만 지우면 돼요.

### 작업 B — 저장 안정화 (P0)
- **문제와 근거**: TOP 10의 2번.
- **목표**: 저장 데이터가 사라지거나 조용히 깨지지 않게 해요.
- **범위**
  - 저장 스키마 버전 필드와 마이그레이션 함수
  - 저장 실패(용량 초과 등)를 화면에 알림
  - 이전 저장본 자동 백업(최근 3개 순환)
  - ⚙️ 설정에 저장 파일 내보내기·가져오기(JSON)
  - 발견 지도 기록(`disc2`) 압축 또는 상한
- **변경 파일**: `index.html`(저장·불러오기 부분과 설정 메뉴)
- **작업량 / 위험**: 중 / 중(기존 저장 호환) → 이전 형식 샘플 저장 파일로 테스트를 추가해서 막아요.
- **완료 기준**
  - 예전 형식 저장 파일을 불러와도 내용이 보존돼요.
  - 강제로 용량 초과를 만들면 경고가 떠요.
  - 내보내기 → 초기화 → 가져오기를 하면 같은 상태로 돌아와요.
- **롤백**: 자동 백업에서 복원해요.

### 작업 C — 몬스터·주민 모델 1차 교체 + 전투 피드백 (P1·P2)
- **문제와 근거**: TOP 10의 4번과 5번.
- **목표**: 화면에 가장 많이 보이는 던전·월드 몬스터를 애니메이션 3D 모델로 바꾸고, 피격·사망·공격 예고를 보이게 해요.
- **범위**
  - Quaternius Ultimate Monsters(CC0)에서 일반 몬스터 6~10종을 골라 웹용으로 변환
  - 공통 애니메이션 모델 로더: 대기·걷기·달리기·공격·피격·사망
  - 몬스터가 죽으면 사망 동작 뒤에 사라지게
  - 몬스터 공격 전 0.3~0.4초 준비 동작 + 공격 범위 표시
  - 플레이어 공격 판정을 칼이 지나가는 시점에 맞추기
- **변경 파일**: `index.html`(몬스터 모델·전투 부분), `assets/monsters/`, `assets/CREDITS.txt`, `docs/ASSET_INVENTORY.md`
- **작업량 / 위험**: 대 / 중
  - 모바일 메모리와 성능 부담이 있어요. 모델을 몬스터마다 복제하지 않고 공유하고, 개체 수 상한을 둬서 줄여요.
  - 기존 밸런스(공격 간격)가 달라질 수 있어요.
- **완료 기준**
  - 교체한 몬스터마다 게임 안에서 6동작이 재생되는 걸 스크린샷과 테스트로 확인해요.
  - 회귀 테스트가 모두 통과해요.
- **롤백**: 모델 로드에 실패하면 기존 도형 모델로 자동 대체하는 구조를 유지해요.

## 3. 단계별 로드맵

| 단계 | 작업 | 목적 | 작업량 |
|---|---|---|---|
| P0 | A 테스트 저장소화 → B 저장 안정화 → 서버 편집 전송을 주변 구역 단위로 변경 | 기존 기능과 데이터 보호 | 중·중·중 |
| P1 | 아트 기준 문서(비율·색·재질) → C 몬스터 1차 → 주민·왕·근위병 교체 → 플레이어 옷 입은 모델 | 화풍 통일 | 중·대·대·대 |
| P2 | 타격감(피격 경직, 히트스톱), 몬스터 AI 상태(경계·추적·후퇴), 보스 패턴, 드롭 연출, 장비 옵션 시너지 | 핵심 전투 재미 | 중~대 |
| P3 | 바이옴별 고유 자원·몬스터·지역 보스, 탐험 도감, 마을 발전·거점 시설(작업장·대장간·창고·사육장) | 탐험과 생활의 연결 | 대 |
| P4 | 실기기 성능 측정 표준화, 구역 생성을 프레임에 나눠 처리(또는 Worker), LOD·그림자 예산, 로딩 화면과 점진 로딩, 모듈 분리 시작 | 안정 실행 | 중~대 |
| P5 | 계정·클라우드 저장, 서버 권한(피해·보상·인벤토리 검증), 마을·집 동기화, 재접속 복구 | 공정한 공동 플레이 | 매우 대 |

## 4. 테스트 계획 (각 작업 공통)

1. 변경 전에 `docs/TEST_BASELINE.md`의 시나리오를 실행해 기준선을 다시 확인해요.
2. 변경한 기능의 새 시나리오를 추가해요(예: 저장 마이그레이션, 몬스터 6동작).
3. 변경 후 전체 회귀 테스트와 스크린샷 비교를 해요.
4. 소프트웨어 렌더링(SwiftShader) 결과와 실기기 결과를 따로 기록해요. 실기기 측정은 사용자 도움이 필요해요.
