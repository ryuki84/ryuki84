# 1. 문서 사용 지침

이 문서는 기존 프로젝트의 전체 핸드오프 문서(`HANDOFF.md`)를 대체하지 않는다.

- `HANDOFF.md`: 기존 구현 현황, 실행 방법, 테스트 방법, 알려진 문제, 작업 이력의 기준 문서
- `GAME_DESIGN_DOCUMENT.md`: 앞으로 만들 게임의 방향과 기능 명세
- `WORK_QUEUE.md`: 실제 작업 순서와 진행 상태

기존 구현을 충분히 분석하기 전에는 대규모 리팩터링이나 전면 재작성을 시작하지 않는다. 기존 기능과 자산을 최대한 재사용하면서 새 설계에 맞춰 점진적으로 발전시킨다.

## Claude가 반드시 지킬 원칙

1. 먼저 현재 저장소와 문서를 읽고 실제 구현 상태를 확인한다.
2. 기존 코드에 이미 구현된 기능을 새로 만들지 않는다.
3. 새 설계와 기존 구현 사이의 차이를 먼저 분석하고 문서화한다.
4. 작업은 작고 검증 가능한 단위로 나눈다.
5. 관련 테스트를 실행한 뒤 전체 회귀 테스트를 진행한다.
6. 테스트 통과만으로 완료 처리하지 않는다. 실제 Claude Artifact 화면에서도 결과를 확인한다.
7. 사용자가 확정하지 않은 핵심 비주얼 방향이나 게임 규칙을 임의로 크게 변경하지 않는다.
8. 기존 기능을 제거하거나 대체해야 한다면 먼저 영향과 이유를 설명하고 승인받는다.
9. 진행 상황에 따라 `GAME_DESIGN_DOCUMENT.md`, `WORK_QUEUE.md`, `HANDOFF.md`를 함께 갱신한다.
10. 사용자가 매 단계마다 지시하지 않아도 명확히 합의된 방향 안에서 다음 작업을 계획하고 진행한다. 다만 방향성·비주얼 취향 등 사용자 판단이 필요한 사항은 비교안을 제시한다.

# 2. 게임의 핵심 방향

## 2.1 한 문장 정의

**포근 마을은 귀여운 판타지 세계에서 자원을 모으고, 제작하고, 건설하며, 자신만의 생활 터전과 세계를 확장해 나가는 생활형 샌드박스 생존·제작 RPG다.**

## 2.2 핵심 재미

가장 중요한 재미는 다음 순환에서 나온다.

1. 새로운 지역을 탐험한다.
2. 나무, 돌, 광물, 식물, 식량 등 자원을 채집한다.
3. 채집한 자원을 가공하고 도구·가구·건축 자재를 제작한다.
4. 집, 작업장, 농장, 마을 시설을 건설한다.
5. 생활 기반과 제작 능력이 발전한다.
6. 더 먼 지역과 희귀 자원에 접근한다.
7. 다시 더 큰 제작과 건설을 진행한다.

전투는 핵심 루프를 보조하는 콘텐츠다. 전투 자체가 게임의 주된 목적이 되지 않도록 한다. 강한 몬스터나 던전은 희귀 자원, 특수 제작 재료, 탐험 보상에 접근하기 위한 선택적 도전 요소로 활용한다.

## 2.3 게임 디자인 원칙

- 자유 샌드박스: 정해진 직업이나 하나의 정답 플레이를 강요하지 않는다.
- 생활 중심: 채집, 제작, 건설, 농사, 동물 돌보기 등 다양한 활동을 존중한다.
- 귀엽고 포근한 판타지: 긴장감만 강조하지 않고 편안한 생활 감성을 유지한다.
- 의미 있는 탐험: 단순히 맵이 넓은 것이 아니라 지역마다 고유 자원과 발견 요소가 있어야 한다.
- 점진적 성장: 플레이어가 실제로 한 활동을 통해 관련 능력이 성장한다.
- 지속성: 플레이어가 만든 건축물과 월드 변경 사항은 저장 후에도 유지된다.
- 접근성: 모바일 터치 환경에서도 핵심 플레이가 가능해야 한다.

# 4. 플레이어 성장과 자유도

플레이어는 특정 직업에 고정되지 않는다. 원하는 활동을 중심으로 성장할 수 있다.

## 4.1 성장 분야

- 채집: 자원 채집 효율, 희귀 자원 발견, 도구 활용
- 제작: 제작 속도, 제작 품질, 고급 레시피 해금
- 건설: 건축 가능 구조물, 건축 효율, 고급 건축 자재
- 탐험: 지역 발견, 지도 정보, 유적과 비밀 탐색
- 생활: 농사, 요리, 동물 관리, 주민 관계
- 전투: 생존과 탐험을 위한 보조 성장

전투를 하지 않는 플레이어도 생활·제작·건설을 통해 충분히 성장할 수 있어야 한다.

## 4.2 숙련도 설계

각 활동을 실제로 수행하면 관련 숙련도가 오른다. 숙련도는 해당 활동을 조금 더 편리하고 효율적으로 만들어야 한다.

예시:
- 나무를 많이 채집하면 벌목 숙련도 상승
- 가구를 제작하면 목공 숙련도 상승
- 건축물을 지으면 건설 숙련도 상승
- 농작물을 재배하면 농업 숙련도 상승

초기에는 복잡한 스킬 트리보다 직관적인 숙련도와 해금 구조를 우선한다.

# 5. 채집 시스템

## 5.1 자원 분류

- 목재: 나무, 가지, 통나무
- 광물: 돌, 철광석, 구리, 수정 등
- 식물: 약초, 꽃, 섬유, 버섯
- 식량: 과일, 채소, 물고기, 고기
- 동물 자원: 털, 가죽, 알 등
- 마력 자원: 마력석, 정령 가루 등

## 5.2 채집 규칙

- 자원 종류에 따라 적절한 도구를 사용한다.
- 지역별로 등장하는 자원을 구분한다.
- 일부 자원은 날씨, 시간, 계절 또는 특정 조건에 따라 등장한다.
- 일반 자원은 일정 조건에 따라 재생성될 수 있다.
- 희귀 자원은 탐험과 발견의 보상이 되어야 한다.
- 채집에는 애니메이션, 사운드, 타격 효과 등 손맛을 제공한다.
- 도구 내구도는 적용할 수 있지만 지나치게 번거로운 관리 요소가 되지 않도록 한다. 수리와 교체가 간단해야 한다.

추후 확장:

- 제작 시 주변 보관함 재료 자동 사용
- 운송 및 대량 보관 기능

## 6.2 제작 분야

초기 제작 분야는 다음을 기준으로 한다.

1. 목공: 도구 손잡이, 가구, 목재 건축물
2. 대장장이: 도구, 무기, 금속 부품
3. 요리: 식사, 회복 음식, 버프 음식
4. 재봉: 의상, 가방, 침구
5. 연금술: 물약, 특수 재료, 마법 아이템

모든 분야를 한 번에 깊게 구현하지 않는다. 핵심 루프에 필요한 레시피부터 구현한다.

## 6.3 제작 품질

제작 품질은 초기에는 단순한 단계로 구성한다.

- 일반
- 우수
- 희귀
- 명장

품질 차이는 능력치뿐 아니라 외형, 내구도, 효율 등으로 표현할 수 있다. 단, 초반부터 과도한 확률·재료 파밍을 강요하지 않는다.

## 6.4 레시피 해금

레시피는 다음 경로로 얻을 수 있다.

- 기본 제공
- 숙련도 달성
- 탐험 중 발견
- 주민에게 배우기
- 던전·보스 보상
- 특정 자원이나 아이템 연구

# 7. 건축 시스템 — 핵심 차별화 요소

건축은 포근 마을의 핵심 콘텐츠다. 다음 세 가지 방식을 모두 지원한다.

## 7.1 블록 단위 자유 건축

Minecraft와 유사한 자유 배치 방식이다.

대상:
- 블록
- 바닥
- 벽
- 계단
- 지붕
- 기둥
- 다리 및 대형 구조물

목표:
- 플레이어가 원하는 형태를 직접 만들 수 있어야 한다.
- 지형과 건축물이 자연스럽게 연결되어야 한다.
- 건축물의 저장·복원과 충돌 판정이 안정적이어야 한다.

## 7.2 모듈 조립형 건축

건축 부품을 조합해 건물을 만드는 방식이다.

기본 부품:
- 바닥 및 기초
- 벽
- 지붕
- 문
- 창문
- 기둥
- 계단
- 발코니 및 장식 부품

목표:
- 일반적인 집, 작업장, 상점, 창고 등을 쉽게 만들 수 있어야 한다.
- 부품 간 연결과 스냅 배치가 직관적이어야 한다.
- 층을 추가하거나 구조를 확장할 수 있어야 한다.

## 7.3 완성형 건물 배치

완성된 건물 프리셋을 선택해 배치하는 방식이다.

기본 흐름:
1. 건물 목록에서 프리셋 선택
2. 배치 미리보기 표시
3. 회전 및 위치 조정
4. 충돌과 지형 조건 확인
5. 필요한 자원 확인
6. 건설 확정
7. 내부 가구와 장식 배치

초보 플레이어도 쉽게 건축을 시작할 수 있게 하는 방식이다.

## 7.4 세 방식의 공통 기능

세 건축 방식은 서로 다른 별도 시스템이 아니라 공통 건축 데이터 모델을 사용해야 한다.

공통 기능:
- 배치 미리보기
- 회전 및 위치 조정
- 충돌 및 지형 검증
- 필요 재료 표시
- 설치 및 취소
- 철거
- 이동
- 복사
- 저장 및 복원
- 가구와 장식 배치

## 7.5 건축 재료 단계

- 원시: 나뭇가지, 잎, 흙
- 목재: 판자, 통나무
- 석재: 돌, 벽돌
- 고급: 금속, 강화 목재, 가공 석재
- 마법: 수정, 마력석, 특수 판타지 재료

## 7.6 구현 순서 권장

1. 완성형 건물 프리셋 배치
2. 건물 내부 가구 배치
3. 모듈형 바닥·벽·지붕 조립
4. 블록 단위 자유 건축
5. 이동·복사·철거 등 편의 기능
6. 고급 재료와 특수 건축

초기부터 모든 기능을 완성하려 하지 말고 공통 데이터 모델을 먼저 설계한다.

# 8. 생존 및 생활 시스템

## 8.1 관리 요소

- 체력
- 허기
- 스태미나
- 체온

수면은 별도의 지속 게이지보다 시간 진행 및 휴식 기능으로 구현하는 것을 권장한다.

## 8.2 상태 간 영향

- 허기가 낮으면 스태미나 회복 효율이 감소한다.
- 스태미나가 낮으면 작업과 채집 효율이 떨어진다.
- 추운 지역에서는 체온 관리가 필요하다.
- 의복, 음식, 거주 공간, 불과 난방 시설이 생존을 돕는다.
- 잠을 자면 시간 진행과 함께 피로가 회복된다.

## 8.3 난이도 원칙

생존 난이도는 보통으로 한다.

- 허기나 체온이 낮아졌다고 즉시 사망시키지 않는다.
- 상태 악화는 단계적으로 표현한다.
- 플레이어가 문제를 인지하고 대응할 시간을 제공한다.
- 관리 요소가 제작과 탐험을 방해하는 과도한 반복 노동이 되지 않도록 한다.

## 8.4 시간과 날씨

우선 구현:
- 낮과 밤
- 기본 날씨
- 비와 눈 등 기상 효과
- 지역별 기온 차이

추후 구현:
- 계절 변화
- 계절별 작물과 자원
- 폭풍 등 특수 기상
- 날씨와 생물 행동의 상호작용

# 9. 농사와 요리

농사 기본 루프:

1. 땅을 준비한다.
2. 씨앗을 심는다.
3. 물을 준다.
4. 성장 상태를 확인한다.
5. 수확한다.
6. 요리하거나 판매·교환한다.

초기에는 2~3종의 작물과 기본 농기구부터 구현한다.

요리는 식량 확보와 생존 관리에 연결한다. 음식은 허기 회복을 기본으로 하고, 일부 음식은 스태미나 회복이나 체온 유지 등 추가 효과를 줄 수 있다.

# 10. 동물과 생태계

동물은 단순한 장식이 아니라 생활과 생산에 연결되는 존재로 발전시킨다.

가능한 기능:
- 발견
- 길들이기 또는 포획
- 먹이 주기
- 친밀도
- 번식
- 생산물 획득
- 탑승 또는 이동 보조

공룡은 기존 프로젝트의 자산과 기능을 재활용하되, 전투 대상만이 아니라 길들이고 기르는 생물로 발전시키는 방향을 검토한다.

초기에는 2~3종의 동물부터 시작한다. 복잡한 번식·생태 시뮬레이션은 후순위다.

# 11. 주민과 마을 발전

주민은 마을에 생동감을 주고 플레이어의 생활을 보조한다.

초기 직업 예시:
- 농부
- 목수
- 대장장이
- 상인
- 요리사
- 탐험가

초기에는 복잡한 자율 AI보다 다음을 우선한다.
- 간단한 하루 일정
- 직업별 작업
- 플레이어가 지정하는 작업
- 생산물과 거래
- 기본적인 친밀도와 대화

마을 발전은 플레이어의 건축과 시설 건설에 반응해야 한다.

# 12. 월드와 탐험

## 12.1 월드 구조

여러 개의 큰 지역이 자연스럽게 연결된 오픈 월드를 지향한다.

절차적 생성은 유지하되 무한히 넓은 지형 자체를 목표로 하지 않는다. 각 지역이 고유한 자원, 생물, 발견 요소, 제작 재료를 제공해야 한다.

## 12.2 초기 지역 구상

| 지역 | 분위기 | 주요 자원 및 특징 |
|---|---|---|
| 초록 초원 (Green Meadow) | 평화로운 시작 지역 | 기본 목재, 돌, 식량, 기초 농사 |
| 속삭임 숲 (Whispering Forest) | 깊고 신비로운 숲 | 희귀 목재, 약초, 숲 생물 |
| 수정 산맥 (Crystal Mountains) | 춥고 험준한 산악 | 광물, 수정, 체온 관리 |
| 고대 정글 (Ancient Jungle) | 고대 유적과 거대 식생 | 특수 식물, 공룡, 유적 재료 |
| 별빛 습지 (Starlight Wetlands) | 마법적인 습지 | 마력 자원, 희귀 생물, 연금 재료 |

지역명과 세부 자원은 추후 실제 월드 구성에 맞춰 조정할 수 있다.

## 12.3 탐험 보상

탐험은 다음과 같은 보상을 제공해야 한다.
- 새로운 자원
- 새로운 생물
- 제작 레시피
- 유적과 비밀
- 희귀 장비 및 장식
- 주민과 이야기
- 새로운 건축 재료

플레이어가 다음 지역으로 이동할 명확한 이유를 제공한다.

# 13. 전투와 던전의 역할

전투는 유지하되 우선순위를 낮춘다.

- 기존 일반 몬스터와 엘리트 몬스터를 재사용한다.
- 전투 보상은 희귀 제작 재료, 레시피, 장비, 탐험 보상과 연결한다.
- 보스는 지역별 주요 도전 콘텐츠로 배치한다.
- 전투를 하지 않는 생활형 플레이도 충분히 성립해야 한다.

기존 아레나 중심 구조는 새 핵심 루프를 방해하지 않도록 역할을 재검토한다. 기존 기능을 제거하기 전에 의존성과 활용 가능성을 분석한다.

- npc: 주민과 작업

# 18. 저장 데이터 설계 원칙

새 시스템을 추가할 때 기존 저장 v3와 백업·복구 흐름을 보존한다. 필요한 경우 버전을 올리고 마이그레이션을 제공한다.

예상 데이터 영역:
- `PlayerData`: 플레이어 위치, 상태, 숙련도, 장비
- `InventoryData`: 소지 아이템과 퀵슬롯
- `WorldData`: 월드 시드, 지역, 시간, 날씨
- `ResourceData`: 채집 노드 상태와 재생성 정보
- `BuildingData`: 플레이어가 설치한 건축물과 배치 정보
- `FarmingData`: 작물과 성장 상태
- `AnimalData`: 길들인 동물과 상태
- `NPCData`: 주민 상태와 작업 배정

## 중요한 저장 규칙

**절차적으로 생성된 기본 지형과 플레이어가 변경한 월드 상태를 분리한다.**

- 생성 가능한 기본 지형은 시드와 생성 규칙으로 재구성할 수 있다.
- 플레이어가 건설한 건축물과 변경한 지형은 별도로 저장한다.
- 로드 시 플레이어 변경 사항이 절차적 생성 결과에 의해 덮어써지면 안 된다.
- 저장 구조 변경 시 기존 세이브를 읽을 수 있도록 마이그레이션을 제공한다.
- 저장 실패나 데이터 손상에 대비해 기존 백업·복구 체계를 유지한다.

# 19. MVP 범위와 완료 기준

## 19.1 첫 번째 플레이 가능한 MVP

첫 MVP는 하나의 시작 지역에서 채집·제작·건설·생활의 핵심 루프가 실제로 이어지는 상태를 목표로 한다.

포함 기능:
- 초록 초원 시작 지역
- 기본 3D 캐릭터와 이동
- 나무, 돌, 식물 채집
- 기본 도구 제작
- 작업대 제작
- 기본 가구와 건축물 제작
- 집과 작업장 건설
- 건물 내부 가구 배치
- 허기, 스태미나, 체온, 수면
- 작물 2~3종
- 기본 동물 2~3종
- 기본 몬스터 2~3종
- 인벤토리·제작·건축·상태 UI
- 월드·인벤토리·건축물 저장 및 불러오기

## 19.2 MVP 수용 테스트

다음 흐름을 처음부터 끝까지 완료할 수 있어야 한다.

1. 플레이어가 나무와 돌을 채집한다.
2. 채집한 자원으로 기본 도구를 제작한다.
3. 작업대를 제작하고 설치한다.
4. 작업대에서 건축 재료와 가구를 제작한다.
5. 집을 건설한다.
6. 집 안에 가구를 배치한다.
7. 허기와 체온을 관리하며 생활한다.
8. 작물을 심고 수확한다.
9. 게임을 저장하고 종료한다.
10. 다시 접속했을 때 플레이어, 인벤토리, 건축물, 농작물 등 진행 상태가 보존되어 있다.

위 흐름이 안정적으로 동작해야 MVP 완료로 판단한다.

## 역할 재검토

- 아레나: 핵심 게임 루프를 보조하는 콘텐츠로 재배치 검토
- 몬스터·보스: 희귀 자원과 탐험 보상에 연결
- 공룡: 전투 대상뿐 아니라 길들이기와 사육 대상으로 확장
- 주민: 단순 NPC에서 생산과 마을 발전에 기여하는 존재로 발전
- 무한 월드: 무한한 크기보다 지역별 고유성과 탐험 동기를 강화

## 기존 핸드오프에 기재된 알려진 문제

Claude는 실제 저장소에서 여전히 유효한지 확인한다.

- 실제 휴대폰 FPS 측정이 아직 충분하지 않음
- VRM 캐릭터 로딩 용량이 큼 (캐릭터당 약 5MB로 기재)
- 원격 플레이어가 마네킹 형태
- 다른 월드의 주민은 동물 위주
- Artifact의 파일 저장 기능이 동작하지 않음
- 2D 가구의 이모지 표시가 폰트에 영향을 받음
- VRM 캐릭터의 현대 의상 문제
- 최신 변경 사항을 포함한 전체 29개 테스트 회귀 확인 필요

# 22. 테스트 및 배포 규칙

기존 핸드오프의 작업 규칙을 유지한다.

1. 작은 변경 단위로 작업한다.
2. 변경 기능과 관련된 테스트를 먼저 실행한다.
3. 전체 회귀 테스트를 실행한다.
4. 테스트가 상태 변경을 기다리도록 작성한다. 고정 시간 대기는 최소화한다.
5. 저사양 환경에서 FPS가 낮을 수 있으므로 테스트 타임아웃을 현실적으로 설정한다.
6. 전체 회귀 테스트 중에는 `index.html`을 수정하지 않는다.
7. 새 에셋을 추가하면 `assets/CREDITS.txt`와 `docs/ASSET_INVENTORY.md`를 갱신한다.
8. 기능 구현 후 실제 게임 화면과 조작을 확인한다.
9. Claude Artifact에 반영하고 모바일에서도 확인한다.
10. 검증 후 커밋과 푸시를 진행한다.

## 기존 실행·검증 명령 (실제 package.json 확인 필수)

```bash
npm install
npm start
npm test
npm run build:artifact
```

기존 테스트는 Playwright 29개 시나리오로 기재되어 있다. 테스트 개수와 실행 시간은 현재 저장소에서 확인한다.

## Artifact 관련 주의사항

기존 배포 과정에서 `data:` URL이 Artifact Viewer에서 차단되는 문제가 있었고, `GLTFLoader.prototype.load`를 패치해 `data:`를 `blob:`으로 변환하는 처리가 필요하다고 기록되어 있다.

**이 패치를 임의로 제거하지 않는다.** 배포 후 실제 Artifact Viewer에서 VRM 및 기타 리소스 로딩을 검증한다.

# 25. 최종 개발 방향 요약

포근 마을의 중심은 전투나 레벨업이 아니라 **플레이어가 직접 세계를 만들고 가꾸는 과정**이다.

채집은 제작을 위한 활동이고, 제작은 건설과 생활을 위한 수단이며, 건설은 플레이어가 세계에 남기는 결과다. 탐험은 더 나은 자원과 새로운 가능성을 제공하고, 생존은 이 활동들에 적당한 계획과 리듬을 부여한다.

따라서 모든 신규 기능은 다음 질문을 기준으로 판단한다.

> 이 기능이 플레이어의 채집·제작·건설·생활·탐험을 더 재미있고 의미 있게 만드는가?

그렇지 않다면 우선순위를 낮추거나 구현하지 않는다.

**첫 번째 목표는 초록 초원에서 자원을 모으고, 도구와 작업대를 만들고, 자신만의 집과 작업장을 건설하며, 저장 후 다시 접속해도 그 세계가 그대로 남아 있는 작은 완성형 플레이 경험을 만드는 것이다.**
